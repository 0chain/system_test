# Firebase / App Login Fix

## Auth Flow

0box generates CSRF and JWT tokens, but requires a valid Firebase ID token first:

1. **Firebase ID Token** — Generated by Firebase Auth (Google). Client authenticates (email/password, phone) and Firebase returns an ID token. This is the "entry ticket."
2. **CSRF Token** — Generated by 0box. The test calls `GET /v2/csrftoken` with the Firebase token in `X-App-ID-TOKEN` header. 0box validates it against Firebase, then returns a CSRF token.
3. **JWT Token** — Generated by 0box. The test calls `CreateJwtToken()` / `RefreshJwtToken()` with the Firebase token. 0box validates, then issues its own JWT.

```
Client → Firebase Auth (email/password) → Firebase ID Token
Client → 0box (with Firebase ID Token) → CSRF Token
Client → 0box (with Firebase ID Token + CSRF) → JWT Token, wallet ops, etc.
```

The Firebase token is the root of trust — without a valid one, 0box rejects everything, which is exactly why all the 0box tests were failing with "test_firebase_token".

## Fix Steps

1. Go to Firebase Console → Project `box-dev-ce8bf` → Project Settings → Service Accounts
2. Click Generate New Private Key for `firebase-adminsdk-fbsvc@box-dev-ce8bf.iam.gserviceaccount.com`
3. Also go to Authentication → Settings → Authorized domains → Add `test.zus.network`
4. Also verify Phone and Google sign-in providers are enabled under Authentication → Sign-in method

## Important Notes

- `FBASE_AUTH_DOMAIN` is the Firebase project domain (`*.firebaseapp.com`), NOT the deployment domain
- Authorized domains must include deployment domain (e.g. `test.zus.network`) in Firebase Console → Authentication → Settings
- With `deployment_mode: 0` (dev mode), 0box bypasses Firebase token validation server-side. But the web app frontend STILL needs Firebase Auth to work (to get the initial ID token). So authorized domains + sign-in providers must be configured regardless.
- The Firebase service account key persists across container restarts (volume-mounted from host)
